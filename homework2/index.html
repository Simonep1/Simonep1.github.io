03 / COMPARE ALGORITHMS

Keccak-256 ≠ SHA3-256

Same permutation, different padding

SHA-2 (including SHA-512) is a distinct family that uses a different design from Keccak. Keccak was selected for the SHA-3 standard, but Ethereum's Keccak-256 differs from NIST's SHA3-256.

Both use the Keccak-f[1600] permutation at the same rate/capacity, but Ethereum's Keccak-256 uses the 0x01 padding suffix, while SHA3-256 uses 0x06 domain separation. Therefore even the same message has different digests.

05 / CONTEXT

How the pieces developed

1977 · RSA

One of the first practical public-key cryptosystems, based on integer factorization.

1985 · Elliptic-curve cryptography

Miller and Koblitz independently propose public-key methods using elliptic curves.

2001 · SHA-2 / SHA-512

The SHA-2 family is introduced in the 2001 revision of the Secure Hash Standard; SHA-512 underlies the HMAC/PBKDF2 steps used here.

2012 · BIP-32

Hierarchical deterministic keys make one seed useful for a tree of accounts.

2013 · BIP-39

Mnemonic phrases make wallet backups easier to represent and recover.

2014 · BIP-44

Conventional multi-account, multi-currency key-derivation paths.

2015 · SHA-3 standard

NIST standardizes SHA-3 from Keccak; Ethereum keeps the pre-standard Keccak-256 variant.

2016 · EIP-55

Mixed-case address checksums improve recognition of accidental typing errors.

06 / TAKEAWAYS

Why not just one algorithm?

Different jobs, different guarantees

  • Key generation: start with high-quality random entropy. Weak entropy cannot be fixed later by derivation.
  • Key derivation: turn one secret into a structured tree of reproducible child keys via PBKDF2/HMAC.
  • Public-key cryptography: use secp256k1 to bind a private signing key to a publicly verifiable key.
  • Hashing: use Keccak-256 to create a compact identifier from the public key.
  • Checksum: use EIP-55 to catch accidental input errors.
  • Encoding: use words and hexadecimal to express bytes for humans; encoding alone provides no secrecy.

What the measurements can show

  • Changes in derivation indices give addresses with no obvious simple numeric relationship.
  • Well-designed hash outputs should exhibit balanced bits and strong diffusion, but a limited experiment cannot certify either property.
  • EIP-55 detects most accidental address typos; it does not prevent intentional substitution by an attacker.
  • SHA3-256 and Keccak-256 produce different outputs for identical input because of domain separation.

Conclusion: secure wallets are built by composing specialized tools. Their outputs may look similar (byte strings), but their security properties and purpose are fundamentally different.
