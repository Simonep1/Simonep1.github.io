01 — Elliptic-curve encryption

This experiment uses exactly the toy curve from Homework 1: y² = x³ + 7 (mod 17), with generator G = (1, 5) and the original modular point addition and double-and-add multiplication. This is a very small illustrative curve, not the full secp256k1 curve.

The private-key input range is 1 ≤ d ≤ 48, as in Homework 1. However, this generator has order 9, so private keys that differ by a multiple of nine produce the same public point.

  1. Key generation: the receiver chooses a private key d and computes the public key Q = dG, where G = (1,5) is the toy generator.
  2. Encryption: the sender chooses an ephemeral scalar r, computes R = rG and shared point S = rQ, and uses the alternating coordinates of the shared point as a simple XOR mask. The ciphertext consists of (R, encrypted bytes).
  3. Decryption: the receiver computes S' = dR. Since d(rG) = r(dG), S' = S, so the same XOR mask recovers the original bytes.

For reproducibility, this demonstration fixes d = 6 and r = 4. The mask simply repeats the two coordinates of the nonzero shared point. This is a teaching example, not secure encryption: its key space is tiny, its mask reveals repeated patterns, and its ephemeral scalar is fixed.

02 — Caesar cipher

The Caesar cipher shifts each English letter by a fixed number of positions in the alphabet. Here we use key k = 7; spaces, punctuation, and case remain unchanged.

Encryption: Ek(x) = (x + k) mod 26
Decryption: Dk(y) = (y − k) mod 26

Both algorithms are reversible given the right key. The important difference is that Caesar changes letters independently in a predictable way, while the elliptic-curve construction first creates a shared secret used to mask the message bytes.

03 — Statistical cryptanalysis of Caesar

For a known language, a sufficiently long reference corpus gives an estimate of expected letter frequencies. Given a Caesar ciphertext, test all 26 shifts: decrypt with each one, count the resulting letters, and select the shift whose distribution is closest to the reference distribution according to the chi-square score (smaller is better).

χ²(k) = Σi=A…Z (Oi,k − Npi)² / (Npi)

Here O is the letter count after decrypting with candidate k, N is the total number of letters, and p is the relative frequency estimated from the included English reference corpus.

04 — Restricted-key attack on ECC

The ECC private key is selected from 48 allowed integers. An attacker who knows the public key Q and generator G can calculate dG for every d = 1, 2, …, 48 and compare the result with Q. Since G has order 9, several candidate values match: the attack can recover an equivalent key, not necessarily the original integer. That equivalent key still computes the same dR and decrypts the message.

Why these attacks work differently

The Caesar attack uses a statistical property of the ciphertext: a fixed substitution preserves natural-language frequency patterns. The ECC attack does not rely on frequencies; it exploits a small private-key space and a public-key check.

A properly configured secp256k1 system uses a generator with a very large order and a private scalar from a roughly 256-bit space. Searching that space is not feasible. Here the tiny subgroup (order 9) is an additional weakness: even without the stated 1–48 restriction, there are only nine different multiples of this generator. The repeated-coordinate XOR mask is also a separate design weakness. Neither weakness should be confused with security properties of real-world ECC.
